# FDEOpen 建设计划与复用判断

## 目标

FDEOpen · FDE开放社区；让企业AI落地更加开放。由 FDE前线发起，独立品牌，不将开放资源设为课程获客门槛。首期以发现、复用、贡献形成完整闭环。

## 已检查的相邻仓库

- `fde-hub`：企业需求与专家撮合，Prisma + API + 多客户端；保留原业务，参考审核与协作边界，不复制耦合服务。
- `51fde`：Next.js 职业成长平台；保留原业务，使用独立部署与数据，提供生态外链。
- `fde-skills`：AGPL-3.0-only 的真实技能目录；首期收录 20 个来源条目，链接原文、保留作者和许可。仅索引，不复制技能实现。

## 结构

- `src/app`：SSR 页面、OAuth 回调、JSON API、SEO。
- `src/components`：统一导航、资源卡片、客户端表单、后台。
- `src/lib`：数据库适配、服务层、认证权限、GitHub同步、验证。
- `content`：真实来源快照、20 项目 / 20 Skills / 20 编辑场景 / 5 专题与 MDX 文档。
- `supabase/migrations`：PostgreSQL 表、视图、约束、索引、RLS。
- `scripts`：迁移、幂等种子、来源核验。
- `tests`：服务层、权限、浏览器主流程与可访问性。
- `docs`：架构、生产部署、运营手册、验收记录、路线图。

## 实施顺序

1. 基础：Next.js 16 / React 19 / TypeScript / Tailwind 4 / shadcn 风格 Radix 基础组件；PostgreSQL SQL 与本地 PGlite 持久化适配；演示身份与真实 GitHub OAuth。
2. Phase 1：首页、项目 / Skill / 场景发现及详情、开发者身份、投稿、审核、收藏、工作台与管理后台。
3. Phase 2：外部 Demo、MDX 开放文档、评论审核、GitHub 元数据缓存与签名 Webhook。
4. Phase 3：共创任务、认领审核、PR 提交与确认贡献、私密企业需求。
5. 验收：类型、Lint、单元 / 集成、端到端、响应式 / a11y / SEO、安全与部署说明。

## 默认边界

- 未配置第三方环境时使用清晰标识的本地演示模式；本地数据库真实持久化。生产模式强制显式配置，禁止回退公开管理员。
- 场景是编辑方案，不声称客户已落地；所有绩效数字必须是用户验证指标而非承诺。
- 不执行外部代码，不默认加载第三方 iframe；外部 Demo 在独立页面打开。
- 无需虚构社区用户或贡献。示例身份只在演示环境出现。
- 未配置外部账号 / 域名时交付可部署源码、说明和本地验收，不声称已上线。

# 社区运营手册

## 开站前的最小准备

1. 完成生产部署和首次管理员授权。
2. 核对 20 个项目与 Skills 的原作者、许可、链接和访问条件。
3. 以真实身份完善编辑资料；不要把演示账号导入生产。
4. 根据团队维护能力确定每日审核与反馈频率。
5. 在公开隐私页补充真实运营主体和联络方式。

## 投稿与内容维护

开发者在 `/submit` 填写资源；GitHub 项目可导入元数据。导入不会自动发布，作者仍需说明场景和使用边界。后台 `/admin?tab=submissions` 检查来源、许可、是否包含隐私、介绍是否实事求是；通过后生成详情页。退回时提供具体修改意见，工作台会收到通知。

投稿者通过工作台提交修改，修改未审核时原内容继续可见，审核后保持 URL 不变。管理员可在内容管理编辑介绍、正文、来源、推荐和发布状态；已创建资源的类型固定，需要不同类型时新建内容；下架用 archived，不删除关联记录。

后台扩展字段使用明确 JSON Schema，例如：

```json
{
  "version": "1.0.0",
  "platforms": ["Codex", "Claude Code"],
  "install": "请阅读原仓库安装指南",
  "dependencies": ["Python 3.10+"],
  "relatedSlugs": ["fde-skills", "enterprise-knowledge"]
}
```

场景可编辑 pain、solution、workflow、metrics、industry、size；Demo 可编辑 demoUrl、input、output；任务可编辑 state(open/in_progress/completed)、deliverables、deadline、issueUrl。relatedSlugs 每次保存都同步关系表，可从两个方向浏览。

MDX 文章在 `content/articles/*.mdx` 通过 Git 修改和版本审查。后台修改文章正文会移除原 MDX 文件绑定并按纯文本发布，避免执行用户提供的代码。若恢复版本管理，可在扩展字段重新设置对应 articleFile。

## 企业需求

需求默认私密。后台查看队列会写入审计日志。未获公开授权时，只保存跟进备注，不可发布为任务。已授权时，另写不含公司信息、联系方式和客户材料的公开标题与描述，再发布。不要把公司收益假设写成验证结果。

需求池承担早期运营跟进，不包含 CRM 自动外呼或自动向用户发邮件。站内通知用于审核反馈。

## 共创贡献

1. 在内容管理建立 task，state=open，写清交付物、难度、期限、关联项目与负责人说明。
2. 申请者介绍计划，管理员接受后允许上传 PR 链接。
3. 管理员打开 PR，核验作者、内容、合并 / 验收情况；确认后生成 contributions。
4. 贡献会显示在主动公开的个人主页。不把“申请已提交”或“已接受”视为已完成贡献。
5. 失败或不适合的申请提供反馈；通过编辑 task state 关闭进一步认领。

## 首页与专题

内容管理设置 featured 控制资源精选。专题管理创建集合、选择包含的资源和主题色，可将集合取消公开。首页配置管理公告与 Lab / 共创 / 开发者模块开关。

首页使用真实目录数量和带日期的 GitHub Stars，不展示虚构注册用户或贡献数量。100 项目共建计划是目标。FDE前线作为内容传播方，51FDE 与 FDE中国保持清晰的独立服务入口。

## 评论、举报与反垃圾

评论默认 pending，通过审核后公开。举报提供原内容、举报人和说明，处理可标记 resolved/dismissed。关联内容如需下架，请另在内容管理归档并记录原因。限流与蜜罐是基础措施；规模增长时可增设 CAPTCHA、人工复核分级与内容策略。

## 数据与账号请求

用户可自行修改资料、取消公开、取消收藏。需要导出 / 删除时，运营在私密需求池核对本人身份，按既定合规流程处理。删除用户前须评估关联贡献和审计记录，优先去标识化而非直接级联删除。正式上线前必须明确责任人、处理期限和联系地址。

## 验收走查

- 以成员登录，搜索 RAGFlow 并收藏，在工作台确认。
- 提交一个带来源的项目；在匿名搜索中确认尚未公开。
- 退出并以管理员登录，通过投稿；确认成员通知和公开详情。
- 成员修改资源，检查审核前原文不变，审核后 URL 不变。
- 认领部署任务、管理员接受、成员提交 PR、管理员核验并确认贡献。
- 提交不勾选公开授权的企业需求，确认管理员不能发布，匿名搜索不到联系方式。
- 提交评论、举报并从后台审核；测试用户角色不能越权。
- 修改公告、精选、专题，刷新公开站确认生效。

当前自动化验收记录见 `ACCEPTANCE.md`。

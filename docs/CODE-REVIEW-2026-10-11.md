# FDEOpen 代码复查与优化记录

日期：2026-10-11。范围：目录与详情数据访问、工作台、后台编辑、投稿与共创事务、认证边界、HTTP 请求、GitHub 同步、页面组件和响应式样式。本次直接修改代码，并以原有业务流程和新增回归用例验证。

## 发现并修复

| 级别 | 原问题与影响                                                         | 修改与证据                                                                                                                                           |
| ---- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1   | Webhook 先取前 25 个项目再按仓库过滤，目录扩大后部分仓库永远不会命中 | 仓库条件提前进入 SQL；支持 `.git/`、大小写；用位于第 25 项之后的仓库回归验证                                                                         |
| P1   | Webhook 过早记录 delivery，异常或进程中断后可能将未完成同步判为成功  | 校验 payload 后抢占；成功后标记完成；失败释放；处理中返回可重试状态；中断后的租约可在 10 分钟后重获；claim token 隔离不同尝试                        |
| P1   | JSON body 先全部读入内存再检查大小，且 `null` 等值可能引发 500       | 流式累计字节数，越限立即取消；只接受 JSON 对象；错误格式返回 400，过大返回 413                                                                       |
| P1   | 并发投稿的查重和收藏切换缺少串行边界                                 | 事务内对用户行使用 `FOR NO KEY UPDATE`，避免重复待审投稿及切换丢失；原生 PostgreSQL 多连接并发验证                                                   |

| P2   | 首页每个模块重复 COUNT，模块关闭后仍查数据库                         | 新增只取卡片的 preview 查询；按开关读取可选模块                                                                                                      |

| P2   | 根布局、页面和 metadata 重复读取用户或详情                           | React `cache` 仅在一次渲染内复用；身份数据不使用跨请求缓存                                                                                           |
| P2   | 常用反向关联、资源计数和用户时间排序缺少索引                         | 新增 003 迁移；增加资源计数、反向关系、工作台、评论索引                                                                                              |

| P2   | 投稿公开链接由前端推断，改 slug 或归档后可能失效                     | 查询实际已发布资源的 kind/slug，未公开时不展示链接                                                                                                   |
| P2   | 编辑不存在的后台资源会进入新建表单，已创建资源可改变类型             | 编辑目标不存在时显示 404；服务端及表单禁止改类型，防止任务/贡献关系语义被破坏                                                                        |
| P2   | 不存在的用户、企业需求可被后台报告为更新成功                         | UPDATE RETURNING 检查实际记录，缺失返回 404                                                                                                          |

## 可复核的优化数据

比较同一组 12 个项目、同一顺序的未压缩 `/api/catalog?kind=project` JSON：

- 原响应：17,131 字节；优化后：7,254 字节；减少 **57.7%**。
- 首页业务 SQL：15 次 → 9 次（默认全部模块开启，不包含认证；去掉 6 次 COUNT）。
- 工作台资料页附加业务 SQL：5 次 → 0 次。
- 工作台收藏页业务 SQL：5 次 → 2 次（统计 + 当前页）。
- 新列表不会把最长可达数万字符的 README/正文带入卡片结果；回归测试使用 20KB 正文与 40KB README 验证。

原始比较记录：[review-performance.json](review-performance.json)。不将本机采样解释为线上延迟承诺；没有跨用户缓存私密数据。

## 升级与后续边界

已有正式数据库需先执行 `npm run db:migrate`，再部署新版。新增 `003_query_indexes.sql` 与 `004_webhook_claims.sql`，均已纳入幂等迁移流程。本地演示会自动执行；不覆盖现有数据。

Webhook 出错不会被永久吞掉，但本次没有引入持久后台任务队列或自动重试调度。失败投递需由 GitHub 侧重投/运营重投，或后续 cron 同步补偿。本文只说明应用具备安全重试能力，不承诺上游自动重投。

搜索仍采用 PostgreSQL ILIKE；当前目录规模下已验证，未进行万级内容/生产网络压力测试。运营后台部分队列仍有 100/200 条显示上限，规模增长后应补充分页。Supabase 真实 GitHub OAuth 仍需部署凭据联调，不能由本地演示替代。开发依赖风险详见 SECURITY。

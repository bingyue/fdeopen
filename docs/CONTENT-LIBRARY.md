## 内容性质

新增「来源整理」状态：来源材料披露的企业实践与指标，不等于本站独立审计结果。案例统一采用此状态；原创观点、选型研究与参考方案采用「编辑观点」。保留原稿已有的事实、推断和方法建议标注。部分采集来源的署名与链接按展示要求省略，公开标注为「公开案例资料整理」；公开资料链接是否仍可访问、原材料披露效果的现状，不能据一次本地导入推断。

匿名源材料仍匿名；修正了结构化源数据把某家电企业误标为联想的问题。相同家电产品知识案例只保留一个版本。未添加虚构人物、活动、访问次数或经营成果。

## 可重复导入

```bash
# 验证完整稿件、分类、图片引用、图片大小、类型和SHA-256，不打开数据库
npm run content:import

# 关闭使用同一个 PGlite 目录的本地服务后，备份数据，再执行
APP_MODE=demo npm run content:import -- --apply --retire-examples
```

对于已配置的PostgreSQL/Supabase环境，先执行数据库迁移，再显式指定现有管理员：`npm run content:import -- --apply --owner=<管理员UUID>`。本轮仅初始化本地数据库。

- 导入采用稳定ID、唯一slug与事务；重复执行跳过既有内容，不覆盖CMS修改或重新发布已下架文章。
- 默认不归档示例；显式 `--retire-examples` 仅归档当前管理员名下未被编辑的原始15篇演示稿，保留记录和附件。
- 原社区资源、账号、收藏、提交与审核记录保持不变。
- 导入摘要在 `.data/content-import/import-*.json`，数据库审计事件为 `media.library.import`。
- 图片位于 `content/media-library-assets/`；导入时复制到配置的上传目录，通过已有附件权限接口提供。原始绝对路径不会进入公开正文。
- 应用启动不扫描本地资料，也不自动重复导入。完整资料包约201篇，只在离线导入时读取。

`npm run content:prepare` 是本机资料归档的构建脚本，要求原始资料目录仍存在；普通部署只需要已生成的 JSON、配图和导入命令，不需要访问作者的本地目录。

```bash
# 只预览初始化资料包的变更，不连接数据库
npm run content:clean-sources

# 停止本地服务并备份 PGlite 目录后，同时清理当前数据库与资料包
```

数据库清理从当前正文生成变更，只更新正文和来源字段，保留其他CMS编辑，事务内检查版本号并递增版本。重复执行不产生新变更；原记录和初始化包自动备份到 `.data/content-import/source-cleanup-*/`，审计事件为 `media.source.cleanup`。非演示数据库需要指定现有管理员 `--owner=<UUID>`。`content:prepare` 在生成资料包后自动应用同一展示规则，防止重新导入时恢复已移除的署名。
